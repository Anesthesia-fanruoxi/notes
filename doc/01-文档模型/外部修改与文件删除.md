# 外部修改与文件删除

只针对**有本地路径的临时文档**（拖入 / 双击 / 打开对话框 / 命令行）。常驻文档在文档库内，不参与这套检测。

## 基线

打开文件时用 Rust 命令 `file_mtime(path)` 记下毫秒级修改时间，写进标签元数据 `diskMtime`。
之后每次「保存到原文件」「重新加载」「保留当前」都会刷新这个基线。

## 检测时机

- 窗口重新获得焦点（`window` 的 `focus` 事件）。
- 切换活动标签。
- 每次只检查当前活动标签，避免无谓的 IO。

不引入文件系统实时监听：打磨阶段先用「聚焦 + 切换」轮询，覆盖绝大多数使用场景。

## 外部修改：提示「已被外部修改」

条件：文件仍存在，但 mtime ≠ 基线。

编辑器顶部出现琥珀色提示条：
「『文件名』已被外部修改，当前编辑的是副本。」+ 两个按钮：

- **重新加载**：读磁盘最新内容替换编辑器；丢弃当前所有修改；删除旧 scratch 快照并按新内容重建；基线 mtime 刷新。
- **保留当前**：只把基线 mtime 推到最新，隐藏提示条；编辑器内容与副本不动。之后再被改还会再次提示。

## 外部删除：提示「已从磁盘删除」

条件：`file_mtime` 返回空（文件不存在）。

编辑器顶部出现红色提示条：
「『文件名』已从磁盘删除，编辑器里是最后一份副本。」+ 两个按钮：

- **恢复文件**：把编辑器里的副本按原编码/换行写回原路径，刷新基线、清脏、隐藏提示，scratch 记录保留。
- **删除记录**：删除 scratch 副本与侧栏记录，关闭标签（磁盘上本来就没有文件了）。

从快照重新打开记录时如果原文件不存在，标签会直接带上「已删除」状态，提示条立刻可见。

## 与保存的关系

- 提示条存在时仍可直接 `Ctrl+S`：有源文件的临时文档会把副本写回原路径，相当于「用当前内容重建文件」，随后提示条消失。

## 已知待打磨

- 只比较 mtime：某些同步盘会保留 mtime，可能漏报；反之仅触碰文件不改内容也会误报。
- 不支持目录级监听，隐藏窗口期间的外部改动要等下次聚焦才提示。
- 常驻文档与文档库目录不做外部改动检测。
