# 大文件降级

## 分档阈值

| 档位 | 条件 | 行为 |
| --- | --- | --- |
| full | < 2MB | 完整功能：语法高亮、折叠、行号、搜索、Markdown 预览 |
| lite | 2–20MB | 关闭语法高亮与折叠，保留行号与搜索 |
| plain | > 20MB 或命中读取上限 | 纯文本：无高亮、无行号、无折叠，仅基础编辑与查找 |

阈值集中在 `src/editor/tiers.ts` 的 `SIZE_LIMITS`，改这里即可调整。

## 提示

- 进入 lite / plain 时编辑区上方出现黄色提示条：
  - 精简模式：已关闭语法高亮，保留搜索与行号
  - 大文件模式：已关闭语法高亮与折叠
- 提示条只说明降级原因，不阻塞编辑。

## 读取上限

- Rust 读取时超过上限会截断，返回 `truncated: true`，前端强制走 plain 档。
- 状态栏仍显示真实体积；保存时按当前副本内容写回（注意：被截断的文档不建议直接保存，避免丢尾部内容——见下）。

## 大文件只读（> 20 MiB）

- 打开前先用 `file_info` 查大小；超过 20 MiB 不再读全文、不建 CodeMirror 状态，直接进入只读查看器。
- Rust 侧用 `memchr` 建行索引，前端按可见窗口调用 `large_file_lines` 取行；正文永远不整篇进入 WebView。
- 行索引按大小 + mtime 失效，最多缓存 4 个文件；UTF-8 / GBK / GB18030 按行解码，UTF-16 暂不支持。
- 查看器支持虚拟滚动、行号、跳转到行；不支持编辑、Markdown 预览、AI 修改与自动快照。
- 大文件临时文档不写 scratch，因此不出现在侧栏临时区，重启后需要重新打开文件。
- 200 MiB 级日志首屏只取一屏，索引在后台线程构建，打开接近秒开。

## 已知待打磨

- 截断文档目前没有「只读/禁止保存」的硬保护。
- 分档只按字节数判断，没有按行数（Markdown 预览另有 3000 行限制）。
- lite / plain 档缺少一键切换回完整模式的入口。
- 大文件查看器暂不支持查找、跨行复制与自动感知磁盘变化；查找计划后续迭代补充。
